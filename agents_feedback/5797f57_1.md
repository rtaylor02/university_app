Based on an analysis of [AGENTS.md](file:///C:/Users/mailb/OneDrive/My%20Documents/GitHub/AI_Full_Stack_Projects/university_app/AGENTS.md), the document covers project setup, service exposure, authentication, and CI/CD well. However, several critical microservice design patterns, database management rules, and API contracts are missing:

---

### 1. Database Schema Migrations (Flyway / Liquibase)
* **What's Missing**: No mention of how schema evolution is managed across the 4 MySQL databases (`student_db`, `course_db`, `enrollment_db`, `auth_db`).
* **Why It Matters**: Relying on Hibernate `ddl-auto: update` or `create-drop` in production leads to schema drift and data corruption.
* **Recommendation**: Add a Flyway/Liquibase convention specifying migration file placement (e.g. `src/main/resources/db/migration`), naming conventions (`V1__init.sql`), and setting `spring.jpa.hibernate.ddl-auto=validate`.

---

### 2. Standardized Global Error Response (RFC 7807 ProblemDetails)
* **What's Missing**: No defined error payload structure for failed API requests or validation errors.
* **Why It Matters**: Without a unified error structure, the React frontend has to handle inconsistent error shapes from `student-service`, `course-service`, `enrollment-service`, and `api-gateway`.
* **Recommendation**: Mandate Spring Boot 4's native **RFC 7807 `ProblemDetails`** or a shared `ErrorResponse` DTO containing `timestamp`, `status`, `error`, `message`, `path`, and `traceId`.

---

### 3. Request Validation (`jakarta.validation`)
* **What's Missing**: No explicit guidelines on payload validation for incoming REST requests.
* **Why It Matters**: Unvalidated DTO inputs lead to unexpected `NullPointerException`s or database constraint violations downstream.
* **Recommendation**: Require `@Valid` on controller `@RequestBody` parameters and explicit validation annotations (`@NotNull`, `@NotBlank`, `@Size`, etc.) on DTO records.

---

### 4. Pagination, Sorting & Search Contract
* **What's Missing**: Rules for how collection resources (e.g., list of students or courses) return paginated data.
* **Why It Matters**: Different services might return arrays vs. Spring Data `Page<T>` wrapper objects, causing React table components to break.
* **Recommendation**: Standardize paginated JSON response contracts (e.g., `content`, `pageNumber`, `pageSize`, `totalElements`, `totalPages`, `last`).

---

### 5. Frontend API Integration & Token Handling
* **What's Missing**: Details on how the React frontend handles JWT storage, header injection, and 401/403 responses.
* **Why It Matters**: Developers/agents may store tokens insecurely or fail to handle token expiration gracefully.
* **Recommendation**: Specify Axios (or Fetch) request interceptors for attaching `Authorization: Bearer <token>` and response interceptors for handling 401 unauthorized redirects to `/login`.

---

### 6. Testing Strategy & Downstream Service Mocking
* **What's Missing**: The document specifies running `./mvnw test` / `./mvnw verify`, but doesn't define testing scope or tools.
* **Why It Matters**: Testing OpenFeign clients without WireMock or Testcontainers leads to flaky integration tests requiring live microservices.
* **Recommendation**: Define testing conventions:
  * Unit tests: `@WebMvcTest` for controllers, `@DataJpaTest` for repositories.
  * Integration/Feign tests: Use WireMock to mock downstream HTTP calls or Testcontainers for real MySQL database integration testing.

---

### 7. CORS & Security Header Policy
* **What's Missing**: No specification on where CORS is configured (Gateway vs. Individual Services).
* **Why It Matters**: Configuring CORS in both Gateway and underlying services causes duplicate `Access-Control-Allow-Origin` headers, breaking browser requests.
* **Recommendation**: Explicitly state that **CORS must be handled exclusively at the `api-gateway` level**, and disabled on private microservices.
